# Лабораторная работа № 6

## Описание работы

В данной лабораторной работе выполняется создание и настройка объектов базы данных в Microsoft SQL Server с использованием языка SQL. Работа выполняется поэтапно с помощью отдельных SQL-скриптов.

Для изоляции объектов лабораторной работы от существующих баз данных была создана отдельная база данных `Lab6_DDL`. Все объекты, созданные в рамках заданий, размещаются в этой базе данных.

## Задание 1. Создание схемы и таблиц

### Цель задания

Создать отдельную базу данных, схему `lab6` и две таблицы — `Customer` и `Product` — с заданными типами данных, первичными ключами и ограничениями целостности.

### Ход выполнения

Работа была разделена на четыре этапа. Каждый этап сохранён в отдельном SQL-файле.

#### 1. Создание базы данных — `1.sql`

Сначала была создана база данных `Lab6_DDL`. Для этого использовалась системная база данных `master`.

```sql
USE master;
GO

CREATE DATABASE Lab6_DDL;
GO
```

Создание отдельной базы данных позволяет выполнять лабораторную работу независимо от существующих баз и не изменять их таблицы.

#### 2. Создание схемы — `2.sql`

В созданной базе данных была создана схема `lab6`, предназначенная для размещения объектов лабораторной работы.

```sql
USE Lab6_DDL;
GO

CREATE SCHEMA lab6;
GO
```

Схема позволяет логически группировать таблицы и обращаться к ним с указанием имени схемы, например `lab6.Customer`.

#### 3. Создание таблицы клиентов — `3.sql`

В схеме `lab6` была создана таблица `Customer` со следующими столбцами:

| Столбец | Тип данных | Назначение |
|---|---|---|
| `CustomerID` | `INT` | Идентификатор клиента, первичный ключ |
| `Name` | `NVARCHAR(100)` | Имя клиента, обязательное поле |
| `City` | `NVARCHAR(50)` | Город клиента, обязательное поле |
| `Email` | `NVARCHAR(100)` | Электронная почта, необязательное поле |
| `CreatedAt` | `DATETIME2` | Дата и время создания записи |

Для таблицы были заданы следующие ограничения:

- `PK_Customer` — первичный ключ по столбцу `CustomerID`, обеспечивающий уникальную идентификацию клиентов.
- `UQ_Customer_Email` — ограничение уникальности для столбца `Email`.
- `DF_Customer_CreatedAt` — значение по умолчанию `SYSDATETIME()`, автоматически устанавливающее текущие дату и время, если значение `CreatedAt` не указано при добавлении записи.

Столбцы `Name` и `City`, а также `CustomerID` и `CreatedAt` объявлены обязательными с помощью `NOT NULL`. Столбец `Email` допускает отсутствие значения.

#### 4. Создание таблицы товаров — `4.sql`

В той же схеме была создана таблица `Product`.

| Столбец | Тип данных | Назначение |
|---|---|---|
| `ProductID` | `INT` | Идентификатор товара, первичный ключ |
| `Name` | `NVARCHAR(100)` | Название товара, обязательное поле |
| `Price` | `DECIMAL(10,2)` | Цена товара, обязательное поле |

Для таблицы были заданы следующие ограничения:

- `PK_Product` — первичный ключ по столбцу `ProductID`.
- `CK_Product_Price` — проверочное ограничение, запрещающее отрицательные значения цены с помощью условия `Price >= 0`.

Столбцы `ProductID`, `Name` и `Price` объявлены обязательными с помощью `NOT NULL`.

**#### 5. Создание таблицы заказов — `5.sql`**

В схеме `lab6` была создана таблица `Orders` для хранения информации о заказах клиентов.

| Столбец | Тип данных | Назначение |
|---|---|---|
| `OrderID` | `INT IDENTITY(1,1)` | Идентификатор заказа, автоматически нумеруемый первичный ключ |
| `OrderDate` | `DATE` | Дата заказа, обязательное поле |
| `CustomerID` | `INT` | Идентификатор клиента, обязательное поле |

Для таблицы были заданы следующие ограничения:

- `PK_Orders` — первичный ключ по столбцу `OrderID`.
- `DF_Orders_OrderDate` — значение по умолчанию, устанавливающее текущую дату, если дата заказа не указана.
- `FK_Orders_Customer` — внешний ключ на `lab6.Customer(CustomerID)`, обеспечивающий связь заказа с существующим клиентом.

Столбец `OrderID` использует свойство `IDENTITY(1,1)`, благодаря которому идентификаторы заказов генерируются автоматически, начиная с 1 с шагом 1. Столбцы `OrderDate` и `CustomerID` объявлены обязательными с помощью `NOT NULL`.

**#### 6. Создание таблицы позиций заказа — `6.sql`**

В схеме `lab6` была создана таблица `OrderLine` для хранения информации о товарах, включённых в заказы, и их количестве.

| Столбец | Тип данных | Назначение |
|---|---|---|
| `OrderID` | `INT` | Идентификатор заказа, обязательное поле |
| `ProductID` | `INT` | Идентификатор товара, обязательное поле |
| `Qty` | `INT` | Количество товара в заказе, обязательное поле |

Для таблицы были заданы следующие ограничения:

- `PK_OrderLine` — составной первичный ключ по столбцам `(OrderID, ProductID)`, обеспечивающий уникальность пары заказа и товара.
- `FK_OrderLine_Orders` — внешний ключ на `lab6.Orders(OrderID)` с каскадным удалением связанных позиций заказа с помощью `ON DELETE CASCADE`.
- `FK_OrderLine_Product` — внешний ключ на `lab6.Product(ProductID)`, обеспечивающий связь позиции с существующим товаром.
- `CK_OrderLine_Qty` — проверочное ограничение, запрещающее нулевое и отрицательное количество товара с помощью условия `Qty > 0`.

Все столбцы объявлены обязательными с помощью `NOT NULL`. Составной первичный ключ не позволяет добавить один и тот же товар в один заказ несколькими отдельными строками.
